## 二、逐项落地

### D1 · PWA

| 项 | 内容 |
|---|---|
| 依赖 | `vite-plugin-pwa`（先写进 Architecture 7.6.1） |
| 配置 | `frontend/vite.config.ts`：`registerType: autoUpdate`、manifest、Workbox |
| 图标 | `frontend/public/icons/`：192 / 512 / maskable 512 / apple-touch 180 |
| 缓存策略 | 静态壳预缓存；`/api` **NetworkOnly**，隐私数据不进 CacheStorage |
| 构建证据 | `dist/manifest.webmanifest`、`dist/sw.js`、precache 28 entries（454 KiB） |
| 离线验证 | `vite preview` 加载一次 → `context.setOffline(true)` → reload，登录页仍完整渲染 |

**边界**：PWA 缓存的是前端壳，不是业务数据；离线时真实 API 仍不可用，演示走 D4 的 fixture。

### D2 · Harness iframe

- Architecture 19.7.6 改为：V1 允许 iframe 嵌 dsh Web UI，token 地址只存 `sessionStorage`；V2 再评估自研。
- 代码不重写：保留 `AssistantView.vue` 的 iframe 方案与“服务没起时给启动说明”的兜底。

### D3 · Scheduler 双进程

- Architecture 6.1 删除“待追认”，明确 API + Scheduler 两个进程是正式架构。
- `deploy.sh` 健康检查后增加 scheduler 运行检查；只起 API 视为部署不完整。
- 本地 `./dev.sh` 默认起 scheduler，`--no-scheduler` 可关。

### D4 · 离线回放

| 项 | 内容 |
|---|---|
| 入口 | 登录页「离线演示（不连后端）」按钮；`?demo=1`；或构建时 `VITE_DEMO_MODE=true` |
| 拦截层 | `frontend/src/api/client.ts` 在 fetch 前查 fixture，命中即返回 |
| 数据 | `frontend/src/demo/fixtures.ts`：登录态、今日、人列表/档案、标签、确认队列、日历、待办、设置、聊天 |
| 写操作 | 返回演示成功响应，不写真实数据库；页面本地状态可继续操作 |
| 退出 | 设置页「退出演示」清 sessionStorage 并回登录页 |
| 测试 | `fixtures.test.ts` 4 条 + `client.test.ts` 1 条“命中 fixture 不发网络请求” |
| E2E | `e2e/cases/demo.mjs` 先把 `/api/**` 全 abort，再进 demo，仍能看今日页与档案 |

**边界**：fixture 是预录数据，不模拟真实抽取；演示里的写操作不会持久化。这不是生产离线缓存。

### D5 · 管理 UI

| 项 | 内容 |
|---|---|
| 页面 | `frontend/src/views/AdminView.vue` |
| 路由 | `/admin`，name `admin` |
| 入口 | 桌面侧栏「账号」（仅 owner）；设置页卡片（仅 owner） |
| 功能 | 账号列表、建号（登录名/显示名/初始密码/角色）、禁用/启用、重置密码 |
| 保护 | 前端非 owner 跳回今日；后端 `/api/admin/*` 仍然 `require_owner`，不是只靠前端 |
| 边界 | 不做删除账号（保留审计与数据归属）；不做角色权限细粒度 |

## 四、已知边界（不是遗漏）

| 项 | 说明 |
|---|---|
| Demo 写操作不落库 | 演示只读 + 本地状态；刷新回到 fixture 初始值 |
| PWA 不缓存 `/api` | 避免把隐私数据写进 CacheStorage；离线业务数据靠 demo fixture |
| 管理 UI 不删账号 | 与后端设计一致：不提供删除，避免审计断链 |
| 管理 UI 的 e2e | 自动化 e2e 账号是 member，只验证非 owner 保护；已用临时 owner 账号手工验证页面列表/入口且无控制台错误；建号/禁用/重置密码由 `tests/api/test_admin.py` 覆盖 |
| Harness iframe 的 X-Frame-Options | 仍可能被上游拦；`AssistantView` 保留“服务没起/被拦”的说明与“新窗口打开” |
