## 四、这一轮踩到的坑（都写进代码注释了）

1. **`SET LOCAL` 不接受绑定参数**（W2 已修）——这次改用 `after_begin` 事件统一下发。
2. **`insert()` 没有 `on_conflict_do_nothing`** ——Postgres 专属语法要用
   `sqlalchemy.dialects.postgresql.insert`。
3. **`await session.execute(...).scalars()` 的括号位置** ——Python 会先 await 再取属性，
   少了括号就变成"coroutine was never awaited"。项目里统一写成
   `(await session.execute(...)).scalars()`。
4. **金额校验不能只靠 Pydantic** ——service 被单测直接调用时绕过了路由校验，
   结果撞上数据库 CHECK 约束抛 IntegrityError（500）。现在 service 里也拦一道，返 400。
5. **日历里"空范围"不等于空列表** ——节日是公共的，任何月份都有。
   所以测试改成"没有个人事件"，不是"没有条目"。
6. **`@dataclass(slots=True)` 没有 `__dict__`** ——序列化响应时 `item.__dict__` 直接抛异常，
   500。改用 `dataclasses.asdict()`。
7. **后台任务必须自己带 user_id** ——抽取任务另开 session，
   而 `raw_inputs` 是 RLS 表，**先查后设变量**会报 `invalid input syntax for type bigint: ""`。
   现在路由把 `user.id` 一起传进后台任务，任务里第一件事就是登记 RLS 变量。
8. **上传目录要跟 cwd 无关** ——`DATA_DIR` 默认取项目根的 `data/`，
   不然从 `backend/` 启动会落到 `backend/data`，跟文档里的路径对不上。

## 五、已知取舍（不是 bug，是刻意决定）

| # | 决定 | 为什么 |
|---|---|---|
| 1 | 综述**不在读档案时同步生成**，而是标记 `summary_stale` 由前端点"重新生成" | 生成要调模型（几秒），不能挂在读接口上。spec 写的是"懒生成后台"，这里退成"显式触发"，避免请求超时 |
| 2 | 标签派生用**规则**（剥前缀 + 取首句），没调模型 | V1 先跑通；规则抽不准再换小模型，见 `services/confirm.py` |
| 3 | 往来**没有 pending 态**，抽取出来直接落库 | spec 明说 V1 就是这样；错了在往来页删 |
| 4 | 限流计数存在**进程内存** | 单容器够用；多副本会按副本数放大，真要精确得上 Redis |
| 5 | 每日任务**默认不常驻** | 多一个常驻进程影响容器行为，留给你决定（见待填写清单第 7 项） |
| 6 | 新增 `notification_channels` 表 | doc 07 的接口清单要它，但 W1 的 12 张表里没有；已补 `0004` 迁移并同步 `docs/06` |
