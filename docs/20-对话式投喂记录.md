> > 我还能在对话框跟它聊天，问喜好什么的。

## 二、逐条记录

### D0 / D1 · 没有对话入口

**修改前**：`IngestView.vue` 只有「批量上传截图」+「说一句话」两段表单，提交后是 `202 排队`，结果要去确认页看。问某个人喜欢什么，只能自己翻档案。

**修复**（前后端各一半）：

| 层 | 文件 | 改动 |
|---|---|---|
| 契约 | `docs/07-后端设计.md` 5.1 | 新增「对话」一节：请求字段、意图路由表、响应字段、三条硬规则 |
| 服务 | `backend/app/services/chat.py`（新建） | 意图判定 + 按人检索 + 投喂回执 |
| 接口 | `backend/app/api/chat.py`（新建） | `POST /api/chat`，multipart，CSRF 必带 |
| 前端 | `frontend/src/views/ChatView.vue`（新建） | 气泡、图片缩略、发送中、失败重试 |
| 前端 | `IngestView.vue` | 页头加「切换到对话」入口（没往底部 tab 塞第七个） |

**为什么是 multipart 而不是 JSON**：要能"边说边甩一张截图"，图只能走 multipart。代价是纯文字也要用 `FormData`，比开两个接口省事。

**为什么同步抽取**：投喂类请求在请求内跑完抽取（3–8 秒），否则没法在一句话里告诉用户"抽到了什么"。所以前端必须有「正在识别」状态，不能让人对着不动的界面等。

### D2 · 意图判定的坑：陈述句里也有"喜欢"

**第一版规则**把 `喜欢 忌口 生日 预算` 当成"在提问"的信号。结果
**「她喜欢喝美式」被判定成查询**——这句话是投喂材料，判成查询就等于把它丢了。

**修复**：问句特征只收**明确的疑问词**（`？ ? 吗 呢 什么 啥 谁 哪 多少 怎么 为什么 几点`）。

**判断依据**：误判的两个方向代价不对等。

| 误判方向 | 后果 |
|---|---|
| 投喂 → 查询 | **材料丢了，用户不知道** |
| 查询 → 投喂 | 多一条垃圾材料，用户看得见，删掉即可 |

所以一律往投喂偏。这条写进了 `chat.py` 的注释和 `docs/07` 那张表下面。

### D3 · 抽取改了别的 session 的状态

**现象**：回执永远是"没抽出能记的事"，实际库里明明有。

**根因**（`chat.py:_handle_feed`）：`extract_from_raw_input` 自己开 session 写 `status='done'` 和事实；请求这边那个 session 的身份映射里还是 `processing` + 零条事实，`session.get()` 直接命中缓存，不会重新查。

**修复**：调完抽取先 `await session.commit()` 收掉当前事务，再 `session.expire_all()`，然后才回查。

```python
await extract_service.extract_from_raw_input(raw_input_id, user_id, person_id)

# 抽取自己开 session 改的 status 和落的事实，本 session 的身份映射里还是旧的：
# 先收掉当前事务再过期，否则读回来的是"处理中 + 零条事实"。
await session.commit()
session.expire_all()
```

**这条不是本模块独有**：任何"在一个请求里同步调用自己开 session 的 service"都会踩。

### D4 · 图片嗅探两处要用

`api/ingest.py` 里原本有个私有的 `_sniff_suffix` + `_MAGIC`。对话接口也要判断图片类型，那就不能复制一份。

**修复**：上移到 `services/storage.py` 的 `sniff_image_suffix()`，投喂和对话共用；删掉原地的副本（不是包一层再调）。

## 三、判定与回答长什么样

**意图路由**（确定性，不额外调模型）

| 顺序 | 条件 | 意图 |
|---|---|---|
| 1 | 带了图 | `feed` |
| 2 | 命中疑问词 | `query` |
| 3 | 带了 `person_id` | `feed` |
| 4 | 其它 | `feed` |

**查询**复用 `facts` + `tags` + `ledger`，**没有新做 RAG**（20 人规模 SQL 更准更快，向量检索是 V2 的事）。实际输出：

```
关于孟雅楠，我记得这些：
· 孟雅楠最近才开始特别喜欢喝苹果汁。（依据：我现在好喜欢喝）
标签：孟雅楠知道朴仁良果汁这个品牌、孟雅楠喜欢喝朴仁良的苹果汁
```

- **只用 `status='confirmed'` 的事实**。没点过确认的不算数——那是"猜"
- **每条尽量带依据**（业务原则 2）
- 一个人都没匹配上时反问，并列出最近记着的几个人

**投喂**回执：

```
这是孟雅楠的，抽出 1 条：
· 下周要去杭州出差
都在确认页，点过「对」才算数。
```

判不出归属时**如实说**（业务原则 3）：

```
材料收下了，但没认出这是谁，事实先没落。去投喂页把它指给某个人，我再抽一遍。
```
