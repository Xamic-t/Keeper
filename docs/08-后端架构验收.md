## 3. 未通过项（5 个，必须修）

### P1 · 应用连库角色不是 `keeper_app`（严重）

| 项 | 内容 |
|---|---|
| **规则来源** | ARCH 15.2-3：*应用连库用普通角色 `keeper_app`，不能用 `postgres`（会绕过 RLS）* |
| **对应文件** | `.env.example:5`、`config.py:31` |
| **实际** | `DATABASE_URL=postgresql+psycopg://keeper:...@localhost:5432/keeper`<br>`APP_DB_USER=keeper_app` 定义了但**代码里没有任何地方使用** |
| **后果** | 如果 `keeper` 恰好是库的 owner，**RLS 会被绕过且不报错**——这是最危险的失败模式 |
| **修复** | ① 建库时创建 `keeper_app` 角色（非 owner）<br>② `DATABASE_URL` 改成 `keeper_app`<br>③ 在迁移脚本里 `ALTER TABLE ... FORCE ROW LEVEL SECURITY` 双保险 |

### P2 · `HTTP_ERROR` 是硬编码字符串（中）

| 项 | 内容 |
|---|---|
| **规则来源** | ARCH 13.2-2：*错误码集中定义在 `core/errors.py`，业务代码里不写字符串* |
| **对应文件** | `core/errors.py:88` |
| **实际** | `code = ErrorCode.NOT_FOUND.value if exc.status_code == 404 else "HTTP_ERROR"` |
| **后果** | 前端拿不到稳定 code，且 `HTTP_ERROR` 不在 14 个枚举内 |
| **修复** | 在 `ErrorCode` 加 `HTTP_ERROR` 枚举，或统一映射到具体 code |

### P3 · 缺 `IntegrityError` → 409 的处理器（中）

| 项 | 内容 |
|---|---|
| **规则来源** | ARCH 13.2-3：*唯一约束冲突要转成 409，不能让它变成 500* |
| **对应文件** | `core/errors.py`（4 个 handler 里没有 IntegrityError） |
| **实际** | 只处理了 `AppError` / `RequestValidationError` / `HTTPException` / `Exception` |
| **后果** | 违反唯一约束时（重复标签、重复提醒）用户收到 **500 内部错误**，而不是"已存在" |
| **修复** | 加一个 `@app.exception_handler(IntegrityError)` 转 409 `CONFLICT` |

### P4 · 异常日志没有 trace_id（中）

| 项 | 内容 |
|---|---|
| **规则来源** | ARCH 14.4：*每个请求生成一个 trace_id，贯穿全链路* |
| **对应文件** | `core/errors.py:47`（`_handle_app_error`）、`core/errors.py:93`（`_handle_unexpected`） |
| **实际** | `logger.warning("app_error code=%s path=%s", ...)` —— **没有 `extra={"trace_id": ...}`** |
| **后果** | 出问题时无法从错误日志串回请求日志，`trace_id` 等于只有一半价值 |
| **修复** | 两个 handler 都从 `request.state.trace_id` 取值并放进 `extra` |

### P5 · `response_model` 零使用（轻）

| 项 | 内容 |
|---|---|
| **规则来源** | ARCH 9.2-2：*响应模型必须写 `response_model`，显式声明 = 自动过滤多余字段* |

## 6. 审计结论

### 6.1 可以放行的部分

- **项目能启动、能响应、能记录、能报错**——四项基础能力有 E4/E5/E6 的机器证据
- **代码规范达标**——ruff 全过，ANN 强制类型注解已生效
- **没有架构性错误**——目录、分层、依赖注入、异常出口都符合规范

### 6.2 不能放行的部分

**5 个问题（涉及 6 条规则），其中 1 个是安全级别**：

> 当前 `DATABASE_URL` 走的是 `keeper` 角色。如果这个角色是库的 owner，
> **RLS 会完全失效且不报任何错**——所有用户看到彼此的数据，而系统看起来一切正常。

这条必须在写第一张表之前修掉，**不能等到 W2**。

### 6.3 一句话
