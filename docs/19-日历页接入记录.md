### C1 · 日历页只有 86 行，是个分堆列表

**修改前**（`frontend/src/views/CalendarView.vue`）：`<input type="month">` + `grouped()`，把 `/api/events` 按 `day` 分堆渲染成卡片。没有网格、没有翻月、没有拖拽。

**根因**：文档选型与代码实现脱节（就是 C0 的下游后果）。

**修复**：

| 层 | 文件 | 改动 |
|---|---|---|
| 依赖 | `frontend/package.json` | `@fullcalendar/{core,vue3,daygrid,interaction}` 全部 **6.1.22**（四包同版本，`^6.1.22` 不会跳到 7） |
| 设计 token | `frontend/src/styles.css` | `@theme` 补 `--color-danger / --color-danger-soft`；末尾加 `.fc` 的 `--fc-*` 变量块 + `.cal-pill` / `.cal-dot` |
| 数据 | `frontend/src/stores/calendar.ts`（新建） | 合并 events + todos，负责改期 |
| 视图 | `frontend/src/views/CalendarView.vue`（重写） | `dayGridMonth` + `zhCn` + `editable` + `dayMaxEvents: 3` |

**关键实现点**（都在 `stores/calendar.ts` 与视图里注释过）：

1. **翻月靠 `datesSet`**：`view.activeStart` 到 `activeEnd`（开区间，减一天才是最后一天）→ 调 `store.load()`。没在 `onMounted` 死拉当月，否则一翻月就是空白。
2. **id 必须带前缀**：`todo-204` / `event-7` / `derived-festival-2026-11-07-3`。两张表自增 id 都是小整数，不前缀必撞车。
3. **改期只改本地，不重拉**：`patchTodoDue` / `patchEventDate` 成功后直接替换本地数组项。重拉会让网格重绘、屏幕跳（HANDOFF2 §六）。
4. **请求序号防串月**：`load()` 内部用 `requestSeq` 丢掉过期响应，快速连点「下月」不会出现「上个月的格子配这个月的标题」。
5. **颜色只在 `eventContent` 里上**：`.fc-*` 的 class 一个没压，色值全部走 `var(--color-*)`，没有写第二套十六进制。

**验证**：

```bash
cd frontend && npx vue-tsc --noEmit -p tsconfig.json   # 无输出，退出码 0
cd backend  && uv run pytest -q                        # 106 passed（数量没变）
cd backend  && uv run alembic current                  # 0005 (head)
cd backend  && uv run ruff check --no-cache .           # All checks passed
```

### C2 · 待办根本不在日历上

**根因**：原实现只拉了 `/api/events`，待办模块是独立页面，两边不共享数据。

**修复**：`store.load()` 用 `Promise.all` 并发拉 `/events?from&to` 和 `/todos?status=open`，前端按 `due_date` 落格。**没有为「区间查询」改接口**——`/api/todos` 只有 `status / due_before / person_id` 三个过滤参数，20 人规模拿全量再过滤足够。

**边界**：`due_date` 为空的待办不进网格（没日子没法落格），页头单独提示「N 条待办没填日期」，不让它们静默消失。

**验证**：待办页把某条 `due_date` 从 11-01 改到 11-12，回日历刷新即在 12 日格子；无日期的那条始终只在页头计数里。

### C3 · 拖拽改期待办

**修复**：`interactionPlugin` 提供 `eventDrop`，按 `extendedProps.kind` 分流：

```ts
if (kind === 'todo') await store.patchTodoDue(rawId, day)          // PATCH /api/todos/{id}
else                 await store.patchEventDate(rawId, old, next)  // PATCH /api/events/{id}
```

**失败必须 `info.revert()`**：后端报错时界面还原，否则用户以为改成功了，刷新一看又回去——比不做还糟。

**验证**（Playwright 真拖，不是读代码）：

```
[e2e] 待办「更新哥姐动态」当前在 2026-11-01
[e2e] 拖拽请求： /api/todos/204 {"due_date":"2026-11-05"}
[e2e] 拖后（未刷新）在 2026-11-05
[e2e] 刷新后仍在 2026-11-05        ← 落库确认
[e2e] 控制台错误： 无
```

派生条目（立冬）也试着拖了一次：**PATCH 请求数 = 0，位置没变**，说明 `editable: false` 生效。

### C4 · 没有颜色区分

**根因**：`todos` 表**没有 priority 列**，`TodoOut` 也不返回这个字段。`services/today.py:47` 的 `priority` 只是排序用的临时权重（提醒 4 / 待办有截止日 5 / 无截止日 6），不是用户可设的优先级。

**修复**：颜色只在渲染层派生，不落库。

| 档 | 判定 | token |
|---|---|---|
| 逾期 | `due_date < today` | `--color-danger` |
| 今天 | `due_date === today` | `--color-warn` |
| 以后 | 其它 | `--color-accent` |

事件按 `type` 分色：生日 `--color-accent-deep`（深陶土）、节日 `--color-success`（绿）、节气 `--color-ink-soft`（灰）、结款 `--color-warn`（琥珀）、自定义 `--color-accent`。

**形状用来区分「待办 vs 事件」**：事件实心（白字），待办描边（淡底 + 同色字与边）。这样 `待办-今天`（琥珀描边）和 `结款`（琥珀实心）不会看混。

**「用户自定义 5 档优先级」没有做**——那是另一个任务：先改 `docs/06`，加 migration 0006，再扩 `TodoCreateIn/UpdateIn/Out`。混进来会同时违反纪律 2 和数据模型。

### C5 · 手机上标题被截成「更…」（新发现，交接文档没预判）

**现象**：iPhone 12（390px）下，7 列每格约 55px，`更新哥姐动态` 只能显示「更…」，日历等于不可读。

**根因**：「手机优先 + 月网格 + 文字标题」三者互相冲突。55px 放 4 个汉字已经是极限，6 字标题必然截断。

**修复**：`eventContent` 按输入设备分两套渲染。

| 设备 | 判定 | 渲染 |
|---|---|---|
| 触屏 | `matchMedia('(pointer: coarse)')` | 9px 小圆点（同色），点开看详情 |
| 指针 | 同上为假 | 文字胶囊 `eventContent` |

同时触屏下 `editable: false`（月网格拖拽要长按，体验极差），改走「点条目 → 弹卡片改日期」这条路——卡片桌面/手机共用，所以桌面点胶囊也能改日期，不是手机专属降级。

**验证**：iPhone 12 模拟下 `.cal-dot = 3 / .cal-pill = 0`，点击 11-12 的圆点，日期卡片正常弹出。

### C6 · 农历生日不能拖（交接文档的规则有漏洞）

**现象**：`docs/18` 定的规则是 `editable = kind === 'todo' || event_id != null`。但 `services/event.py:108` 的 `_expand_lunar_birthday` **会给农历生日也带上 `event_id`**（因为它确实来自 events 表），于是农历生日被判成"可拖"。

**后果**：拖完之后 `PATCH occurs_on` 不生效——农历日期只由 `lunar.month/day` 决定，`occurs_on` 根本不参与计算。刷新就弹回原处，直接违反验收第 3 条「刷新页面还在新日期」。

**修复**：`stores/calendar.ts` 里把判定改成

```ts
const computedEveryYear = item.type === 'birthday' && item.lunar   // 每年现算的，拖了不生效
const writable = item.event_id !== null && !computedEveryYear
```

**这是对 `docs/18` §3.3 的修正**，理由已写进代码注释：让一个拖了会弹回去的条目可拖，等于骗用户。

## 四、一个环境坑（会重复踩）

**vite 只会启动时做依赖预构建。** 装了新依赖之后，正在跑的 dev server 会对新包返回
`504 (Outdated Optimize Dep)`，页面表现为「日历页白屏、控制台报 Failed to fetch dynamically imported module」。

浏览器刷新几次**都不管用**，必须重启：

```bash
# 停掉旧的 dev server，然后
cd frontend && npx vite --force    # 或直接 ./dev.sh
```

验收时为了不动用户在跑的 5173，另起了一个 5174 专门跑 Playwright，测完关掉。
