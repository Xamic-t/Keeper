## 一、功能清单（V2 共 14 项，分两组）

### A 组：Harness 接回来当编排层（6 项）

| 编号 | 功能 | 做什么 | 为什么必须 | 验收 |
|---|---|---|---|---|
| **A1** | Harness 侧车重新接入 | 用 `dsh --profile headless`（一次任务一个进程，不开端口、不留 token 粘贴）作为编排层；主服务作为 BFF 调它 | 你要的就是 Harness 做编排，不是我们手写 JSON 协议 | `docs/38` 里的可行性实测：`keeper_today` 工具被调用并回数据 |
| **A2** | 用户级短期令牌 | 每轮签一个绑定 user_id 的 3 分钟令牌给子进程，侧车用它调接口 | 现在只有一个全局 token（冒充 owner），多用户下 tester 建待办会建到 Admin 名下 | 用 tester 跑一轮，数据落在 tester；用 Admin 令牌访问 tester 数据被 RLS 挡住 |
| **A3** | 工具从"只读 5 个"扩到"读 + 写" | 保留 5 个读工具；新增 `create_todo` / `create_event` / `add_fact` / `create_ledger`（写）；新增 `search`（RAG 检索） | 你要"助理能帮我建待办"，写工具必须存在 | 工具调用后数据库真的有行，且 `add_fact` 只落 pending |
| **A4** | 对话页对接 Harness（**同一个「助理」tab**） | 前端不再走我们手写的 JSON 协议，改为 SSE 连 `/api/conversation/turn/stream`，后端转发 dsh 的 NDJSON 事件 | 不新增页面、不新增菜单，就在现有第 3 个 tab 里 | 页面仍是 7 个 tab；发一句话能看到模型回复 |
| **A5** | 工具调用可视化 | 把 `thinking / tool_call / tool_result` 渲染成气泡下的时间线（可折叠、失败标红） | 你要"调用工具也展示到对话框" | 回复下方出现「调用 keeper_today ✓ 0.3s」这类步骤 |
| **A6** | 降级与开关 | Harness 不可用（没装 / 超时 / 崩）时自动回退到现有原生对话，并在气泡里说明 | 侧车挂了不能让人没法记事（§19.7.3 第三条） | 关掉 harness 目录后，助理仍能回答（走原生） |

## 五、唯一需要你拍板的一件事（其余我按上面执行）

**Embedding 用哪个？** 这决定 RAG 能不能开工，也决定要不要新依赖。

| 选项 | 说明 | 代价 |
|---|---|---|
| **A. 你填 `DASHSCOPE_API_KEY`** | 阿里百炼 `text-embedding-v3`，1024 维，正好对上 `docs/06` 已定的 `vector(1024)` | 要一个 Key（有免费额度）；数据出本机 |
| **B. 本地模型 `fastembed`（bge-small-zh）** | 完全离线，512 维（表字段要改成 512） | 加一个 Python 依赖 + 首次下载 ~100MB；CPU 编码，20 人规模够用 |
| **C. 先不做向量，用关键词检索** | `ILIKE` + 标签，先把"检索工具"这条链打通 | 语义召回弱（"喝茶"搜不到"白茶"），以后还要重做 |

我的建议：**B**。理由：你是单人部署、数据敏感（聊天截图），离线最稳；512 维对 20 人规模足够；
A 需要你去申请 Key 且数据出本机，C 等于绕开 RAG 本身。

你回一个 A/B/C，我就从 T0 开始按批次做，每批做完给你一条可验证的结论（不是"我做完了"）。
