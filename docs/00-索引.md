## 这轮讨论定死的十五件事

### 产品层

1. **双轨**：毕设即 MVP 首发，同一套代码，论文讲机制、产品讲价值
2. **人 × 关系**：哥姐就是客户，一个人可同时持有多个关系角色
3. **需求感知优先级**：关系温度 > 生活切口 > 消费意图
4. **需求感知的内核**：温度 × 场景的 2×2 —— 知道什么时候**不打扰**
5. **主数据链路**：聊天截图（80% 有用信息在一对一私聊里）
6. **画像形态**：分层 —— AI 综述负责"读一个人"，标签负责"筛一批人"
7. **活跃窗口**：推送只管最近 20 人，旧的自然沉底
8. **V1 只做记忆系统**，温度放 V2（需要 3-4 周数据才能算准）
9. **V1 提醒可以日期驱动，但 AI 建议不能砍**
10. **记忆会过期**：每条事实带半衰期，这是动态画像和静态标签的分水岭

### 技术层

11. **产品形态**：响应式 Web + PWA（不做小程序、不做 App、不做纯后端）
12. **前端**：Vue 3 + TypeScript + Vite（不用 HTMX，不用 React）
13. **后端**：Python 3.13 + FastAPI + SQLModel（一个进程，不用 Redis/Celery）
14. **数据**：PostgreSQL 17 + pgvector + 本地文件（企业级，从第一天就按多用户设计）
15. **多用户隔离**：RLS 行级安全，四层防护（表结构 / 数据库策略 / 应用变量 / 文件目录）
16. **模型**：DeepSeek `deepseek-flash`（主）→ 通义 `qwen-vl-max`（备），代码层抽象可切

### 部署层

17. **服务器**：国内云（2 核 4G）+ Docker Compose + Caddy（同域托管前端 + 反代 API）
18. **域名备案前置**：PWA 必须 HTTPS，备案是国内部署的第一周任务

## 一句话概括这个项目

> 传统工具要求人把信息整理成结构再录入。
> 这个系统反过来——人只提供原始材料，由大模型完成理解、结构化、判断和主动提醒。
>
> **它不是记录系统，是判断系统：回答的不是"他是什么人"，而是"我现在该做什么"。**

## 三个原创设计（也是论文最值钱的部分）

1. **需求感知 = 温度 × 场景的 2×2 矩阵**
   把"该不该打扰"变成可计算、可解释的判断，而不是玄学。

2. **记忆半衰期**
   事实按类别设置衰减周期，过期自动降权。这是"动态画像"和"静态标签"的根本区别。

3. **活跃窗口（20 人社交带宽）**
   温度同时是画像维度和推送开关。一个指标两个用途，砍掉了整个注意力调度模块。

---

## 三个技术决策（也是答辩时的"选型对比"素材）

1. **为什么不用小程序**：订阅消息是一次性授权，长期主动提醒做不了——和核心需求直接冲突
2. **为什么不用 RAG 解决一切**：精确事实和跨人筛选走 SQL 更准更快，RAG 只用于模糊回忆和知识增强
3. **为什么模型要抽象一层**：DeepSeek 实验模型转正，识图准确率必须实测；`VisionClient` 一层抽象让换模型不改业务代码
