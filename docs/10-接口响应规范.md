## 1. HTTP 状态码总表

**原则：能用 HTTP 标准状态码表达的，绝不新造。**

| 场景 | 状态码 | 有响应体 | 说明 |
|---|---|---|---|
| 列表查询成功 | `200 OK` | ✅ | 带 `meta` 分页 |
| 详情查询成功 | `200 OK` | ✅ | 单个对象 |
| 创建成功 | `201 Created` | ✅ | 带 `Location` 头 |
| 更新成功 | `200 OK` | ✅ | 返回更新后的完整对象 |
| 删除成功 | `204 No Content` | ❌ | **不能有 body** |
| 空列表 | `200 OK` | ✅ | `data: []`，**不是 404** |
| 参数格式错误 | `400 Bad Request` | ✅ | Pydantic 校验失败 |
| 状态不允许 | `400 Bad Request` | ✅ | 如已确认的卡片再确认 |
| 未登录 | `401 Unauthorized` | ✅ | 带 `WWW-Authenticate` 头 |
| 账号密码错 | `401 Unauthorized` | ✅ | 与"未登录"同码，不同 code |
| 无权限 | `403 Forbidden` | ✅ | 角色不够 |
| 资源不存在 | `404 Not Found` | ✅ | **越权访问也用这个** |
| 唯一约束冲突 | `409 Conflict` | ✅ | 重复标签、重复提醒 |
| 文件过大 | `413 Payload Too Large` | ✅ | 单张图 > 8MB |
| 限流 | `429 Too Many Requests` | ✅ | 只用在登录 |
| 系统异常 | `500 Internal Server Error` | ✅ | 带 `trace_id`，**无堆栈** |
| 上游模型失败 | `502 Bad Gateway` | ✅ | DeepSeek / 通义都挂了 |
| 上游超时 | `504 Gateway Timeout` | ✅ | 模型超时 |

### 1.1 为什么不用 422

FastAPI 的 Pydantic 校验失败**默认返回 422**，但我们统一转成 **400**。

| 理由 | 说明 |
|---|---|
| 422 的历史包袱 | 原名 "Unprocessable Entity"，源自 WebDAV，语义是"格式对但语义错" |
| 前端处理成本 | 很多 HTTP 客户端和网关对 422 支持不好，容易漏判 |
| 团队认知 | "参数错就是 400"是更普遍的直觉 |

代价：语义上"参数格式错"和"参数语义错"都用 400，靠 `error.code` 区分（`VALIDATION_ERROR` vs `INVALID_STATE`）。

## 2. 两种数据结构：列表 vs 对象

**这是最容易做错的地方。** 一句话区分：

> **列表是"给人扫的"，对象是"给人读的"。**

| 维度 | 列表（List） | 对象（Object） |
|---|---|---|
| 数据形态 | `data: [...]` 数组 | `data: {...}` 单个对象 |
| 字段粒度 | **精简**（只放列表项需要展示的） | **完整**（含关联、统计、时间戳） |
| 是否带分页 | **必须** `meta` | 不需要 |
| 是否需要总数 | **必须** | 不需要 |
| 模型类 | `PersonListItem` | `PersonDetail` |
| 典型接口 | 人列表、待办列表、往来明细 | 档案详情、创建后、更新后 |
| **常见错误** | 把详情模型塞进列表 → N+1 查询、响应几十 KB | 把列表项模型用在详情 → 字段不够，前端要再发一次请求 |

### 2.1 三个必须遵守的约定

**① 列表项不查关联表**
列表里出现 `tags: [...]` 这种字段，必须在 service 里用**一次批量查询**拿全，不能在循环里逐个查（N+1）。

**② 对象可以是聚合体**
详情不一定是"一行表数据"，可以是多表拼出来的聚合对象（`person` + `relationship` + `counts`）。

**③ 金额用字符串，不用浮点**
`"12400.00"` 而不是 `12400.0`。JSON 没有 Decimal，用 float 会精度丢失（0.1 + 0.2 ≠ 0.3）。前端展示直接用字符串，计算时再转。

**响应**：`201 Created`

```
Location: /api/persons/21
```

```json
{
  "data": {
    "id": 21,
    "nickname": "陈姐",
    "aliases": [],
    "platform_ids": {},
    "avatar_path": null,
    "contact": {},
    "note": null,
    "created_at": "2026-10-28T00:41:00+08:00",

      "stage_source": "auto",
      "total_in": "0.00",
      "total_out": "0.00"
```

| 项 | 说明 |
|---|---|
| 统一处理 | 路由 `status_code=201` + `ok()`；`Location` 头由路由显式设置 |
| 返回完整对象 | 前端不用再发一次 GET |
| 事务 | `persons` + `relationships` 两个 insert 在同一事务 |

### 3.4 更新成功 `[仅设计]`

**请求**：`PATCH /api/persons/19` body `{ "nickname": "王姐（建材）" }`

**响应**：`200 OK`

```json
{
  "data": {
    "id": 19,
    "nickname": "王姐（建材）",
    "updated_at": "2026-10-28T00:41:30+08:00",
    "relationship": {
      "stage": "core",
      "stage_source": "manual",
      "total_in": "12400.00",
      "total_out": "3200.00"
    }
  }
}
```

| 项 | 说明 |
|---|---|
| 统一处理 | `ok()` |
| **返回完整对象，不是只有改动的字段** | 否则前端要自己合并，容易出错 |
| `PATCH` 语义 | 只改传了的字段；没传的保持不变（区别于 `PUT` 全量覆盖） |

### 3.5 删除成功 `[仅设计]`

**请求**：`DELETE /api/persons/19`

**响应**：`204 No Content`

**响应体：空**。

| 项 | 说明 |
|---|---|
| 统一处理 | 路由返回 `Response(status_code=204)`，**不走 `ok()`** |
| 硬规则 | **204 不能有 body**——有 body 会被部分 HTTP 客户端判为协议错误 |
| 副作用 | 级联删 10 张表 + 删文件，事务与文件操作分离 |

## 4. 空列表 `[仅设计]`

**请求**：`GET /api/persons?keyword=不存在的人`

**响应**：`200 OK`

```json
{
  "data": [],
  "meta": {
    "total": 0,
    "page": 1,
    "size": 20,
    "total_pages": 0,
    "has_next": false
  }
}
```

| 项 | 说明 |
|---|---|
| 统一处理 | 同 3.1，`ok([], meta={"total": 0, ...})` |
| **关键** | **空列表是 200，不是 404**。404 只表示"资源本身不存在"，不表示"集合为空" |
| 前端 | 应该显示空态引导，而不是错误提示 |

## 5. 错误场景（6 个 + 4 个附赠）

### 5.1 参数错误 `[已实现]`

**触发**：`GET /api/persons?size=999`（size 上限 100）

**响应**：`400 Bad Request`

```json
{
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "参数校验失败",
    "detail": {
      "errors": [
        {
          "field": "query.size",
          "reason": "Input should be less than or equal to 100"
        }
      ]
    }
  }
}
```

| 项 | 说明 |
|---|---|
| 抛出点 | Pydantic v2（框架自动） |
| 统一处理 | `core/errors.py` 的 `_handle_validation` |
| 注意 | `field` 用 `query.size` / `body.nickname` / `path.id` 前缀，前端能定位到具体位置 |
| 证据 | 当前代码已有此 handler，可用 `/api/persons?size=999` 之外的任何校验失败触发 |

### 5.2 未登录 `[已实现]`

**触发**：清掉 cookie 后访问任意业务接口

**响应**：`401 Unauthorized`

```
WWW-Authenticate: Cookie realm="keeper"
```

```json
{
  "error": {
    "code": "UNAUTHENTICATED",
    "message": "请先登录"
  }
}
```

| 项 | 说明 |
|---|---|
| 抛出点 | `deps.get_current_user` |
| 统一处理 | `core/errors.py` 的 `_handle_app_error` |
| **规范要求** | RFC 7235：401 **必须**带 `WWW-Authenticate` 头。当前代码**未实现**（见第 7 节差距 G2） |

### 5.3 无权限 `[仅设计]`

**触发**：`member` 角色访问 `POST /api/admin/users`

**响应**：`403 Forbidden`

```json
{
  "error": {
    "code": "FORBIDDEN",
    "message": "没有权限"
  }
}
```

| 项 | 说明 |
|---|---|
| 抛出点 | `deps.require_owner` —— **待实现**，按 19.6 等第一个 admin 接口出现再加 |
| 统一处理 | `_handle_app_error` |
| 与 401 的区别 | 401 = 你是谁不知道；403 = 知道你是谁，但你不能做这个 |

### 5.4 资源不存在 `[已实现]`

**触发**：`GET /api/persons/9999`

**响应**：`404 Not Found`

```json
{
  "error": {
    "code": "NOT_FOUND",
    "message": "找不到这个人"
  }
}
```

| 项 | 说明 |
|---|---|
| 抛出点 | service 层（查不到就 `raise AppError(ErrorCode.NOT_FOUND, ...)`） |
| 统一处理 | `_handle_app_error` |
| **关键设计** | **越权访问也返回这个**——不返回 403，避免泄露"这个资源存在" |

### 5.5 系统异常 `[仅设计]`

**触发**：任何未捕获异常（如数据库连接中断、代码 bug）

**响应**：`500 Internal Server Error`

```json
{
  "error": {
    "code": "INTERNAL_ERROR",
    "message": "服务器内部错误",
    "trace_id": "a1b2c3d4e5f6"
  }
}
```

| 项 | 说明 |
|---|---|
| 统一处理 | `_handle_unexpected` |
| **必须带 `trace_id`** | 用户报错时报这一串，开发者能在日志里精确捞到 |
| **不能带堆栈** | 堆栈只进日志，不进响应 |
| 当前状态 | handler 存在，但**没返回 trace_id**（见差距 G1） |

## 6. 谁在哪里统一处理（一张表看完）

| 场景 | 抛出点 | 处理器 | 文件 |
|---|---|---|---|
| 列表 / 详情 / 创建 / 更新成功 | 路由最后一步 | `ok()`（分页辅助待加） | `core/response.py` |
| 删除成功 | 路由返回 `Response(204)` | 不经过包装 | 路由自身 |
| 参数错误 | Pydantic（自动） | `_handle_validation` | `core/errors.py` |
| 未登录 | `deps.get_current_user` | `_handle_app_error` | `core/errors.py` |
| 无权限 | `deps.require_owner`（待实现） | `_handle_app_error` | `core/errors.py` |
| 资源不存在 | service 层 | `_handle_app_error` | `core/errors.py` |
| 唯一冲突 | 数据库 | `_handle_integrity`（**待加**） | `core/errors.py` |
| 系统异常 | 任意 | `_handle_unexpected` | `core/errors.py` |
| HTTP 语义错误（如 405） | Starlette | `_handle_http` | `core/errors.py` |

**一句话**：**成功走 `core/response.py`，失败走 `core/errors.py`，路由里一行 `try/except` 都没有。**

## 8. 业务错误码规范

### 8.1 格式与命名

| 项 | 规则 |
|---|---|
| **字符集** | `^[A-Z][A-Z0-9_]{2,39}$`（全大写、下划线、3-40 字符） |
| **结构** | `<域>_<具体问题>`，域可省略（表示通用错误） |
| **例（通用）** | `VALIDATION_ERROR`、`NOT_FOUND`、`INTERNAL_ERROR` |
| **例（带域）** | `PERSON_NOT_FOUND`、`LEDGER_AMOUNT_INVALID`、`REMINDER_ALREADY_SENT` |
| **禁止** | 拼接参数值（`PERSON_19_NOT_FOUND`）、中英文混写、小写字母、带空格 |

### 8.2 谁能加、加在哪

| 项 | 规定 |
|---|---|
| **唯一真源** | `app/core/errors.py` 的 `ErrorCode` 枚举 |
| **文档同步** | 加完必须同步 `07-后端设计.md` 4.3 节的表格 |
| **谁维护** | 项目负责人（当前：你本人）。**不接受"临时加一个"** |
| **新增流程** | ① 判断现有码能否覆盖 → ② 不能才加枚举 → ③ 加文档 → ④ 通知前端加分支 |
| **废弃规则** | **只加不删**。废弃的码保留，标注 `DEPRECATED`，前端可以先留着分支 |

### 8.3 现有 14 个码

```
VALIDATION_ERROR    参数校验失败              400
INVALID_STATE       状态不允许这个操作        400
UNAUTHENTICATED     未登录                    401
BAD_CREDENTIALS     账号或密码错              401
ACCOUNT_LOCKED      账号被锁                  401
FORBIDDEN           没有权限                  403
NOT_FOUND           资源不存在                404
CONFLICT            唯一约束冲突              409
FILE_TOO_LARGE      文件过大                  413
UNPROCESSABLE       参数合法但业务不允许      422
RATE_LIMITED        请求过频                  429
INTERNAL_ERROR      系统异常                  500
AI_UPSTREAM_ERROR   模型服务不可用            502
AI_TIMEOUT          模型超时                  504
```

> ⚠️ 发现一个不一致：`07-后端设计` 4.3 节里 `UNPROCESSABLE` 标的是 `422`，但 `ARCHITECTURE` 1.1 说"不用 422"。
> **本规范裁定：`UNPROCESSABLE` 统一改回 `400`**，语义靠 `code` 区分。需同步修 `07`。

### 8.4 前端怎么用

```
1. 先看 HTTP status 分大类（4xx 用户问题 / 5xx 系统问题）
2. 再看 error.code 分具体分支
3. 永远不看 error.message（文案会改，code 不会）
4. 500 类错误：展示 trace_id，提示"把这一串发给开发者"
```

## 9. 一张图记住

```
成功
 ├─ 列表   → 200 + {data: [...], meta: {total, page, size, total_pages, has_next}}
 ├─ 对象   → 200 + {data: {...}}
 ├─ 创建   → 201 + {data: {...}} + Location
 ├─ 更新   → 200 + {data: {...}}（完整对象）
 └─ 删除   → 204 + 空

失败（全部 {error: {code, message, detail?}}）
 ├─ 400  参数错 / 状态不对
 ├─ 401  未登录 / 密码错 / 被锁
 ├─ 403  角色不够
 ├─ 404  不存在（含越权）
 ├─ 409  唯一冲突
 ├─ 413  文件太大
 ├─ 429  太频繁
 ├─ 500  系统异常 + trace_id
 ├─ 502  模型挂了
 └─ 504  模型超时
```
