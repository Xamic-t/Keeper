# 31 · 本地启动与使用

> 一句话：**在项目根目录跑 `./start.sh`，浏览器打开 <http://127.0.0.1:5173>，用 `Admin` / `adminadmin` 登录。**
> 停掉：`./start.sh stop`。看状态：`./start.sh status`。

---

## 一、第一次跑之前（只做一次）

| 需要 | 检查命令 | 说明 |
|---|---|---|
| Docker Desktop | `docker ps` | 数据库跑在容器里，不用在本机装 PostgreSQL |
| uv | `uv --version` | 后端依赖与虚拟环境（`brew install uv`） |
| Node 20+ / pnpm | `node -v` / `pnpm -v` | 前端（`corepack enable` 就有 pnpm） |
| `.env` | `ls .env` | 没有就 `cp .env.example .env`，至少填 `DB_PASSWORD`、`APP_DB_PASSWORD`、`SECRET_KEY` |

后端依赖第一次会自动装（`uv sync` 由 `uv run` 触发）；前端 `node_modules` 缺了，`start.sh` 会自动跑一次 `pnpm install`。

> ⚠️ 现在 `.env` 里的 `APP_DB_PASSWORD` **还没填**、`SECRET_KEY` 里含 `change-me`。
> 本地能用，但上线前必须换——跑 `./scripts/preflight_deploy.sh` 会逐条提示（见 `docs/29` A-4/A-5）。

## 二、日常三条命令

```bash
./start.sh            # 起：数据库 → 迁移 → 后端 → 前端（起完就可以用，日志进 .run/logs/）
./start.sh status     # 看：谁在跑、端口通不通、数据库健康度
./start.sh stop       # 停：后端 + 前端一起停（数据库容器保留，数据在 Docker 卷里）
```

其他：

| 命令 | 用途 |
|---|---|
| `./start.sh restart` | 改完代码想重来一遍 |
| `./start.sh logs` | 跟后端日志（Ctrl+C 只退出查看，不停服务） |
| `./start.sh logs frontend` | 跟前端日志 |
| `./start.sh --scheduler` | 额外起每日任务调度器（每天 08:00 扫事件、生成并推送提醒） |
| `BACKEND_PORT=8001 ./start.sh` | 换端口（默认 8000/5173；也可以 `FRONTEND_PORT=5174`） |

**为什么用 `start.sh` 而不是 `dev.sh`**：

| | `dev.sh` | `start.sh` |
|---|---|---|
| 运行方式 | 前台，Ctrl+C 全停 | 后台常驻，关终端不影响 |
| 适合 | 一边改代码一边看（`--reload`） | **起好了我要用**、给别人演示 |
| 日志 | 混在终端里 | `.run/logs/*.log`，可随时 tail |
| 停止 | Ctrl+C | `./start.sh stop` |
| 状态 | 看不出来 | `./start.sh status` |

## 三、起来之后看什么

| 地址 | 是什么 |
|---|---|
| <http://127.0.0.1:5173> | 前端页面（**平时就用这个**） |
| <http://127.0.0.1:8000/docs> | 接口文档（可直接点着调） |
| <http://127.0.0.1:8000/api/health> | 健康检查，返回 JSON 就是活的 |
| <http://127.0.0.1:5173/?demo=1> | **离线演示模式**：不连后端、用预录数据，断网也能走完整流程（答辩兜底用） |

**账号**：`Admin` / `adminadmin`（owner）；`vb@test.com` / `Verify-pass-1`（member，用来验证"两个人互相看不见"）。
本地开发用弱密码，上线前必须换。

## 四、日志与排错

日志都在 `.run/logs/`（`.run/` 不进 git）：

```bash
tail -f .run/logs/backend.log
tail -f .run/logs/frontend.log
```

| 现象 | 原因 / 怎么办 |
|---|---|
| `端口 8000 被占用（pid xxx）` | 上次没停干净：`./start.sh stop`；或换端口 `BACKEND_PORT=8001 ./start.sh` |
| `数据库 30 秒内没变成 healthy` | Docker Desktop 没起；看 `docker compose logs db` |
| 页面打开是白屏，控制台 `/api` 502 | 系统代理把 `127.0.0.1` 也代理了。浏览器/系统代理里把 localhost 加进"忽略"，或先关代理 |
| 迁移报错 | 先看 `docker compose ps` 是否 healthy；再 `cd backend && uv run alembic upgrade head` 看完整报错 |
| 改了代码没生效 | `uvicorn` 这里是**不带 --reload** 的（后台跑的进程重载容易状态错乱）。改完后端跑 `./start.sh restart`；前端 vite 会自己热更新 |
| 想彻底清零 | `./start.sh stop && docker compose down && docker compose up -d db && ./start.sh`（**`down -v` 会删数据卷，别乱用**） |

## 五、这套启动做了什么（照着排错时看）

```
./start.sh
  ├─ 1/4 docker compose up -d db          PostgreSQL 17 + pgvector，等 healthy
  ├─ 2/4 alembic upgrade head             把库结构升到最新（幂等，跑多少次都一样）
  ├─ 3/4 uvicorn app.main:app :8000       后端；起完 curl /api/health 确认真活了
  ├─ (可选) python -m app.jobs.daily --serve   每日任务调度器
  └─ 4/4 pnpm dev :5173                   前端；起完 curl / 确认真活了
```

要点：
- **服务是不是真起来了**不是看进程在不在，而是脚本会等 HTTP 200（各最多 40 秒），失败直接把日志尾巴打给你；
- 后端进程用 `nohup` 起的，**关终端不会停**；停只能 `./start.sh stop`；
- 数据库容器**不在 stop 范围内**——停它用 `docker compose stop db`，数据在卷 `customers_system_pg_data` 里，不会丢。

## 六、给答辩/演示用的最短路径

```bash
./start.sh                       # 1. 起服务
open http://127.0.0.1:5173       # 2. 打开页面，Admin / adminadmin 登录
./start.sh stop                  # 3. 演示结束，收工
```

如果现场网络不行（投喂要调模型、后端要连库），直接开 `?demo=1` 走离线回放，
不连后端、不调模型、不写数据库，流程一样能演完。
