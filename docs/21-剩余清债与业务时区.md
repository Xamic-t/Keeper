## 二、逐条记录

### T1 · "今天是哪天"按 UTC 算（最严重的一条）

**现象**：2026-11-02 凌晨 01:37 跑 `uv run python -m app.jobs.daily`，输出是

```
daily job done date=2026-11-01
```

**根因**：容器 TZ 是 UTC，而"今天"是从 UTC 取的：

| 位置 | 旧代码 |
|---|---|
| `app/jobs/daily.py:31` | `reference = today or datetime.now(UTC).date()` |
| `app/services/today.py:209` | `reference = today or datetime.now(UTC).date()` |
| `app/api/events.py:61` | `date.today().replace(day=1)` |
| `app/services/chat.py:122` | `Event.occurs_on >= date.today()` |

北京时间 0 点到 8 点之间，`date.today()` 返回的还是昨天。后果：

- **今日页显示昨天的任务**——产品第一屏，早上 7 点打开是错的
- **生日当天的 T-0 提醒提前一天发**——提醒产品的全部价值就是"当天"

**修复**：新增 `app/core/clock.py`，业务日期统一走 `local_today()`（`Asia/Shanghai`）：

```python
BUSINESS_TZ = ZoneInfo("Asia/Shanghai")

def local_today() -> date:
    return datetime.now(BUSINESS_TZ).date()
```

四处调用点全部换掉。**时间戳不动**：`sent_at` / `created_at` / 日志照旧 UTC，
`ARCHITECTURE` 8.6 的"时间必须带时区"依然成立——时间戳和业务日期是两件事，这次把它们分开写清楚了。

**为什么不做多时区**：产品是单区域的（用户都在国内）。将来真要做，把时区挪进用户设置表，调用方不用改。

**验证**：

```bash
uv run python -m app.jobs.daily   # date=2026-11-02（改之前是 11-01）
```

`tests/core/test_clock.py` 钉住：时区必须是 Asia/Shanghai、偏移必须是 +8、`local_today()` 必须等于北京日历日。

### T2 · 导出 ZIP 文件名可穿越目录（Zip Slip）

**根因**（`api/export.py:45`）：`f"persons/{person.id}-{person.nickname}.json"` 直接拼昵称。
昵称写成 `../../etc/x`，解压时条目就跳出导出目录。

**修复**：加 `safe_name()`，只放行「文字 / 数字 / 下划线 / 连字符 / 汉字」，其余替换成下划线；纯符号的名字退化成 `person`。

**验证**：`"../../etc/passwd"` 里不再出现 `/` 和 `..`；`"孟雅楠"` 原样保留；`"///"` → `person`。

### T3 · 图片 MIME 永远写 `image/jpeg`

**根因**（`services/vision.py:60`）：`_image_part(image, mime="image/jpeg")` 用了默认值，
调用处 `_image_part(image)` 从来没传过 mime。png / webp 也标成 jpeg，
有的服务会直接拒收，有的按 jpeg 解码出错——直接影响识别准确率。

**修复**：mime 按**字节**判（复用 `storage.sniff_image_suffix`），嗅探失败才退回 jpeg。
顺手把没用的 `mime` 参数删掉——没人传它。

**验证**：1×1 的 PNG → `data:image/png;base64,...`。

### T4 · 提醒模板里 `{tags}` 永远是空数组

**根因**（`services/reminder.py:131`）：`"tags": []` 写死的。模板里 `"tags": {tags}` 那行
永远渲染成 `[]`，模型少了一整个维度（只有事实、没有结构化标签）。

**修复**：`_person_context()` 多查一次 tags（**过滤掉 `expires_at` 已过期的**），
`_render_prompt()` 多收一个参数，渲染成 `[{"key": "preference", "value": "只喝手冲"}]`。

> **没有新建 prompt 版本**：模板文本一个字没改，`{tags}` 这个占位符本来就在，
> 只是从来没被填过。改的是数据，不是 prompt。

**验证**：prompt 里能出现 `"tags": [{"key": "preference", "value": "只喝手冲"}]`。

### T5 · 待办页 / 设置页零错误处理

**根因**：`TodosView.load()` 只有 `finally { loading = false }`，没有 `catch`；
`SettingsView` 五个动作全部裸调 `await api.xxx()`。接口一错就是静默白屏——用户只看到"什么都没变"。

**修复**：

| 文件 | 做法 |
|---|---|
| `TodosView.vue` | 每个动作 try/catch，统一 `error` ref，页面上显示一条红字 |
| `SettingsView.vue` | 加一个 `guard()` 小函数收口，所有接口调用过它；顶部显示错误条 |

> `ConfirmView` / `TodayView` / `PersonDetailView` 已经有 catch（`docs/17` F1 那轮加的），
> 评审 P3-1 说的"所有页面"其实只剩这两页。

### T6 · 设置页只能配企微

**现象**：后端 `ChannelIn.kind` 支持 `wecom` 和 `pushplus`，前端表单把 `kind: 'wecom'` 写死了，
PushPlus 那条路在界面上根本走不到。

**修复**：加一个类型切换（企微 / PushPlus），输入框的提示语和提交字段跟着切；
空通道时给一条醒目提示"现在提醒只会存进今日页，手机上收不到"；补上"去哪儿拿 webhook / token"。

**为什么现在做**：`HANDOFF2` W14-A（提醒真机推送）卡的就是"没有通道"。
界面能配了，配完点「测试」就能立刻知道通不通。
