## 三、已拍板的决策（**不要再重新讨论**）

### 3.1 库：`@fullcalendar/vue3` **6.x**

| 依据 | 位置 |
|---|---|
| 前端完整清单里写着「日历 = `@fullcalendar/vue3`，MIT 核心版，`eventContent` 返回 Vue 组件」 | `docs/05-产品形态与技术栈.md:74` |

| 「日历 = FullCalendar 6.x（MIT 核心版）」 | `docs/03-数据与技术.md:550` |
| 技术栈一页纸 | `docs/00-索引.md:79` |

**为什么是 6 不是 7**（npm 上 `latest` 已经是 7.1.3，不指定版本会装错）：

1. 文档写的是 6.x；装 7 要先改三处文档，违反宪法纪律 2（先改文档再改代码）
2. **v7 自带一套主题体系**（`skeleton.css` + `theme.css` + `palettes/*.css`，5 套皮肤），和本项目手写的暖米色 token 是两套设计语言，覆盖成本高；**v6 自动注入样式，只需改变量**
3. v7 需要额外装 `temporal-polyfill`
4. v6 是训练数据里的默认版本，示例语料最多（符合 `docs/05` §2.1「只用最主流写法」）

### 3.2 被排除的备选

| 库 | 为什么不用 |
|---|---|
| **Schedule-X** | 拖拽现在是付费插件 `@sx-premium/drag-and-drop`，而拖拽正是本次核心需求 |
| **vue-cal 4.10** | MIT、零依赖、更轻，但月网格拖拽手感要自己调，中文文档和代码语料远少于 FullCalendar |
| **手搓网格** | 正是 `docs/05` §2.4 说的「自己写不出来」那块，不要碰 |

### 3.3 其它约束

- **不引入任何 UI 组件库**（宪法 §二 纪律 1 + `docs/05` §2.4）
- **拖拽只对「可写」条目开放**：`event_id != null` 的自定义事件 + 待办。节日、节气、关系表派生的农历生日是算出来的，拖了没有意义 → `editable: false`
- **本次不做「用户自定义优先级」**，原因见 §五.3。要做得另开任务

## 五、数据现状（写代码前必须知道）

### 5.1 日历事件

```
GET /api/events?from=YYYY-MM-DD&to=YYYY-MM-DD
→ CalendarItem[]   // frontend/src/api/types.ts
  { day, title, type, person_id, event_id, lunar }
```

- `type` ∈ `birthday | festival | solar_term | payment_due | custom`
- **`event_id` 为 `null` = 派生条目**（节日、节气、关系表来的农历生日）→ 不可拖、不可改
- **没有颜色字段**，颜色由前端按 `type` 决定
- 改期：`PATCH /api/events/{id}` body `{ "occurs_on": "YYYY-MM-DD" }`（带 CSRF，`api.patch` 已自动处理）

### 5.2 待办

```
GET /api/todos?status=open
→ TodoOut[]   // { id, title, detail, due_date, status, source, ... }
```

- 改期：`PATCH /api/todos/{id}` body `{ "due_date": "YYYY-MM-DD" }`
- 后端用 `payload.model_dump(exclude_unset=True)`，**只传 `due_date` 不会误清其它字段**，安全
- 列表接口只有 `status` / `due_before` / `person_id` 三个过滤参数，**没有「区间查询」**
  → **前端拿到全部 open 待办后自己过滤即可**（20 人规模，量很小）。不要为了这个改接口

### 5.3 为什么「优先级」只能派生

`backend/app/services/today.py:47` 里确实有个 `priority`，但它**只是排序用的临时权重**：

```python
priority: int = 5                      # 提醒按 level 映射到 4
priority = 6 if todo.due_date is None else 5   # 待办：有截止日 5、没有 6
```

`todos` 表**没有 priority 列**，`TodoOut` 也不返回这个字段。所以本次只能派生三档：

| 档 | 判定 | 颜色 |
|---|---|---|
| 逾期 | `due_date < today` | 新增 `--color-danger` |
| 今天 | `due_date === today` | `var(--color-warn)` |
| 以后 | 其它 | `var(--color-accent)` |

要做「用户自己定优先级 + 5 档颜色」，是**另一个任务**：先改 `docs/06-数据库设计.md`，加 migration 0006，再扩 `TodoCreateIn/UpdateIn/Out`。**不要混进本次。**

## 六、实施步骤

### 6.1 样式对齐（~30 分钟）

v6 的样式是运行时自动注入的，**不需要 import 任何 CSS**。染色只改变量。在 `frontend/src/styles.css` 末尾追加：

```css
/* FullCalendar v6：只改变量，别去 hack .fc-* 的 class */
.fc {
  --fc-border-color: var(--color-border);
  --fc-page-bg-color: var(--color-surface);
  --fc-today-bg-color: var(--color-accent-soft);
  --fc-event-bg-color: var(--color-accent);
  --fc-event-border-color: var(--color-accent);
  --fc-button-bg-color: var(--color-accent);
  --fc-button-border-color: var(--color-accent);
  --fc-button-hover-bg-color: var(--color-accent-deep);
  --fc-button-hover-border-color: var(--color-accent-deep);
  --fc-button-active-bg-color: var(--color-accent-deep);
  --fc-button-active-border-color: var(--color-accent-deep);
}
```

同时给 `@theme` 补一个缺的 token（现在只有 `success` / `warn`，没有 danger）：

```css
--color-danger: #c0392b;
--color-danger-soft: #fbe9e7;
```

> ⚠️ FullCalendar 自己生成 DOM，**Tailwind 的 class 加不进去**。要改外观只有两条路：CSS 变量、或 `eventContent` 插槽。想靠 `@apply` 或 `!important` 去压 `.fc-*` 会越写越脏。

### 6.2 建 store（~30 分钟）

新建 `frontend/src/stores/calendar.ts`：

- `state`：`items: CalendarItem[]`、`todos: TodoOut[]`、`range: { from, to }`
- `load(range)`：`Promise.all` 并发拉两个接口
- `patchTodoDue(id, day)`：调 `PATCH /api/todos/{id}`，成功后**直接改本地数组**，不重新拉
- `events`（computed）：合并成 FullCalendar 的事件数组

合并后的单项形状：

```ts
{
  id: `todo-${t.id}` || `event-${e.event_id}`,   // ⚠️ 必须带前缀
  title,
  start: day,
  allDay: true,
  backgroundColor, borderColor,
  editable: kind === 'todo' || event_id != null,
  extendedProps: { kind: 'todo' | 'event', rawId, personId },
}
```

> ⚠️ **id 必须带前缀。** `todos.id` 和 `events.id` 都是小整数，直接混用必然撞车，撞了后果是拖 A 改了 B。

### 6.3 替换 `CalendarView.vue`（主线，1–2 小时）

保留 `PageHeader`，其余重写：

```vue
<script setup lang="ts">
import FullCalendar from '@fullcalendar/vue3'
import dayGridPlugin from '@fullcalendar/daygrid'
import interactionPlugin from '@fullcalendar/interaction'
```

## 七、已知的坑

1. **装到 7 会全盘不同**：v7 的 import 路径变成 `@fullcalendar/vue3/daygrid`，还要 `temporal-polyfill` 和显式 `skeleton.css`。代码里出现这些东西 = 版本装错了。
2. **列表页操作后不要 `await load()`**：HANDOFF2 §六明令禁止。本地更新视图，否则后端排序一抖屏幕就跳（`docs/17` 的 F1 就是栽在这）。
3. **日历「空范围」不等于空列表**：节日是公共的，任何月份都有。别写「这个月没数据」的测试（`docs/W3-W10` 第 5 条）。
4. **手机**：月网格拖拽在触屏上要长按，体验很差。本项目是手机优先（PWA + 底部 tab），建议 `matchMedia('(pointer: coarse)')` 为真时把 `editable` 关掉，改成「点开卡片改日期」。
5. **农历生日去重别搞坏**：`services/event.py` 里的 `covered` 逻辑是 W12 修 P1-4 时加的，保证同一个人只出现一条（`docs/15` P1-4）。改渲染层不能绕过它。
6. **层叠**：`AppShell` 的侧栏是 `fixed`，FullCalendar 的弹层可能被压在下面，必要时给 `.fc` 提 `isolation` / `z-index`。
7. **提交推送要带代理**：`git -c http.proxy=http://127.0.0.1:7897 -c https.proxy=http://127.0.0.1:7897 push`
8. **不要读 `.env`**（用户明确要求）。
