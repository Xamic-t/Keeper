## 一、写代码时按这个顺序翻文档

**不要通读，按需查。**

| 你要做的事 | 翻哪份 | 看哪一节 |
|---|---|---|
| 建表 / 改字段 | `06-数据库设计` | 5.x 对应表 |
| 写一个接口 | `07-后端设计` | 5.2 对应规格 |
| 定响应长什么样 | `10-接口响应规范` | 3.x 成功 / 5.x 错误 |
| 不知道代码放哪个文件 | `ARCHITECTURE` | 11.3 目录责任表 |
| 想加个封装 / 依赖 | `ARCHITECTURE` | **19.6 三条判定** |
| 文档之间打架 | `13-验收汇总` 第八节 / `ARCHITECTURE` 21 | 优先级 |
| 不确定某个模块怎么写 | `09-最小模块演练` | 整套流程 |
| 判断"这样算不算违规" | `CONSTITUTION` | 工程五纪律 |

**一句话**：**`06` 定表 → `07` 定接口 → `10` 定响应 → `ARCHITECTURE` 定放哪。**

## 二、写一个模块的标准动作（9 步）

照抄 `09` 的十步清单，去掉"改文档"（文档已经写完了）：

```
1. models/xxx.py          写表定义（照 06 的字段表，一个字段都不能少）
2. alembic 迁移            不手工建表
3. services/xxx.py        业务逻辑（不 import fastapi，能单测）
4. tests/services/        先写测试，能脱离 HTTP 跑
5. api/xxx.py             路由 + 请求/响应模型（≤30 行）
6. api/router.py          挂一行
7. curl 验证              看响应格式、状态码、日志
8. 第二账号交叉验证        看 RLS 有没有生效
9. commit + push          push 记得带代理
```

**第 4 步和第 8 步最容易跳过，但它们是唯一能证明"对"的环节。**

## 四、第一周，具体到今天做哪一步

如果现在就开始，**只做这一件事**：

### Day 1（今天）：修 P1 + 起数据库

```bash
# ① 启动 Docker Desktop（当前 daemon 未运行）

# ② 起库
cd /Users/xamic/Customers_System
docker compose up -d db
docker compose ps                        # 期望 STATUS = healthy

# ③ 建普通角色（不要用 owner）
docker compose exec db psql -U keeper -d keeper -c \
  "CREATE ROLE keeper_app LOGIN PASSWORD '换成强密码';"
docker compose exec db psql -U keeper -d keeper -c \
  "GRANT CONNECT ON DATABASE keeper TO keeper_app;"

# ④ 改 .env 的 DATABASE_URL，把 keeper 换成 keeper_app

# ⑤ 验证连接
cd backend && uv run python -c "
import asyncio
from app.db import check_database
print(asyncio.run(check_database()))
"
# 期望：{'status': 'ok'}

# ⑥ 验证健康检查
curl -s --noproxy '*' http://127.0.0.1:8013/api/health
# 期望：HTTP 200，status: ok
```

**今天做完这一步，`13` 里唯一阻塞业务的 P1 就清了，W1 的建表可以开始。**
