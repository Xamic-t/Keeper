## 三、为什么会犯这种错（不找借口）

1. **新功能默认"塞进已有页面"，没有先定义层级。**
   助理先做成设置页里的一张卡片，账号管理先塞进业务侧栏——两次都是"能放下就放"，
   而不是"它属于哪一层"。**功能存在 ≠ 位置正确**，这是最根本的一条。

2. **加了新入口，没清旧入口。**
   助理进了一级菜单、账号进了后台，但设置页那两张卡片还在。
   这不是设计问题，是**收尾没做**：改一处就以为改完了，没有回头把同一功能的所有入口列一遍。

3. **没有任何机制防止再犯。**
   路由表、导航、设置页三者各写各的，谁也不知道"这个页面还有没有别的入口"。
   孤儿页 `/chat` 能一直躺着就是证据——加了页面，没人核对入口。

4. **把"文档里写清楚了"当成"界面上讲清楚了"。**
   `/chat`、投喂、助理的边界我只写在 `docs/07` 和代码注释里，界面上一个字没提。

## 四、目标结构（建议，等你点头）

```
┌─ 业务区（AppShell）：今日 · 投喂 · 助理 · 人 · 确认 · 日历 · 待办
│   手机：底部 5 个（今日 / 投喂 / 助理 / 人 / 更多▾）
│         更多 = 确认 · 日历 · 待办 · 设置
├─ 个人区（二级）：设置 = 账号与安全（改密码 / 退出）
│                         通知（推送通道）
│                         数据（导出 / 保留原图）
│                         关于（版本 / 离线演示）
└─ 管理区（独立裸布局）：概览 · 账号 · 行为 · 系统
     顶部加一条：「你正在以管理员身份使用 Keeper 后台 | ← 返回应用」
```

配套的三条规矩：

| 规矩 | 落地方式 |
|---|---|
| 一个功能只有一个入口 | `nav.ts` 是唯一事实源；重复入口不允许 |
| 每条路由必须归类 | `router/ia.test.ts`：一级菜单 / 二级入口 / 孤儿，三者必须选一 |
| 设置只放"偏好与账户"，不放功能页入口 | IA 测试断言 `settings` 不在一级菜单；review 时检查设置页 |

**已经落地的护栏**（这次一起做的）：
`src/nav.ts`（导航唯一事实源）+ `src/router/ia.test.ts`（7 条断言）——
以后再加页面忘了归类、或把功能页塞进一级菜单，`npm test` 直接红。
