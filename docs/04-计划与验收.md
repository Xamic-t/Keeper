# 04 · 计划与验收

> 前置阅读：`01` `02` `03` `05`
> 本文定义**分几期做、每周做什么、怎么算做成了、什么情况下该停**。
> 约束前提：**一个人，约 18 周（4.5 个月）**。前端采用 Vue 3 前后端分离后，比原 16 周方案多出 2 周（脚手架、类型生成、SPA 部署各占一部分）。

---

## 1. 分期策略

三期，但只有 V1 是必须完成的。V2 决定毕设的高度，V3 决定产品的天花板。

| 期 | 定位 | 周期 | 核心命题 | 完成后能说什么 |
|---|---|---|---|---|
| **V1** | 记忆系统 | W1-W12 | 人投喂，AI 记得住 | "它替我记得" |
| **V2** | 判断系统 | W13-W15 | AI 知道该不该出手 | "它替我想" |
| **V3** | 泛化 | 毕设后 | 换个行业也能用 | "它不只对我有用" |

**分期铁律**：V1 没跑通（自己天天在用），绝不开始 V2。因为 V2 的所有算法都依赖 V1 积累的真实数据，V1 不成立，V2 就是纸上谈兵。

---

## 2. 里程碑

### V1 · 记忆系统（W1-W12）

> **开发顺序：先后端跑通，前端只做「能用的丑版」，最后两周统一换皮。**
>
> 为什么这么排：前端改动便宜（改一个组件文件），数据库和接口改动贵（牵连迁移、类型、调用方）。
> 所以先把表结构和 API 冻结，前端随便换。但**不能不做前端**——没有界面就没法真实使用，
> 没法真实使用就验证不了 VLM 抽得准不准，那才是这个项目最大的风险。

| 周 | 任务 | 交付物 | 验收动作 |
|---|---|---|---|
| **W1** | 数据库定稿（**PostgreSQL + RLS**）+ 后端骨架 + **前端脚手架（空壳，只跑通路由）** | 表结构、RLS 生效、两端能起 | **第二个账号登入，查不到第一个账号的数据** |
| **W2** | **API 契约定死**（OpenAPI 冻结）+ 登录 + 人 CRUD | 接口文档、`openapi-typescript` 能生成类型 | 两个账号各建一人，互不可见；类型零报错 |
| **W3** | **部署上线**（Docker Compose 三容器 + Caddy 同域 + 域名 + SPA 回退） | 手机能访问的真实网址 | 手机打开、刷新 `/person/1` 不 404、添加到主屏 |
| **W4** | 截图上传 + 存储 + 去重 + 异步（**后端**）+ 一个只够用的上传页 | 能传能存 | 传 10 张图不卡 |
| **W5** | **VLM 三步抽取**（**后端**）+ 结果先裸打在页面上 | 图 → 结构化 JSON | 抽 30 张真实截图，人工核对准确率 |
| **W6** | 确认队列 + 落库 + 级联（**后端**）+ 极简确认页 | 能 ✓ / ✗ / 改 | 传图 → 确认 → 档案有内容 |
| **W7** | 画像综述 + 标签 + 时间线（**后端**）+ 极简档案页 | 数据齐 | 打开档案，10 秒内知道这人是谁 |
| **W8** | 日历 + 往来（**后端**）+ 极简日历页 | 数据齐 | 建一个农历生日，算对公历 |
| **W9** | **提醒 + AI 建议 + 企业微信推送** | 手机能收到带建议的提醒 | 造一个 3 天后的生日，看能不能收到 |
| **W10** | 待办 + 端到端走通 + **开始真实使用** | 全链路能跑 | 完整走一遍一天 |
| **W11-W12** | **前端换皮**：按 `docs/design/` 的 v5 重做 | 界面与设计稿一致 | 登录 / 今日 / 人 / 档案 四屏上线 |

> **W3 就要上线，不要攒到最后。** 一个能随时在手机上打开的网址，会让后面九周的开发状态完全不同——你会真的开始用它，而"自己用"是最好的需求来源。
>
> **W10 之后界面还是丑的，但功能是全的。** 这一周开始你就该真的用它，记录所有不顺手的地方——这些记录决定 W11 换皮时该优先打磨哪里。

### V2 · 判断系统（W13-W15）

| 周 | 任务 | 交付物 |
|---|---|---|
| **W13** | 温度五维计算 + 历史快照 + 活跃窗口 | 每个人有分、有趋势、有依据 |
| **W14** | 需求感知 2×2 + 状态驱动提醒 | "这个人可能凉了/他在忙，别打扰" |
| **W15** | 对话式问答 + 混合路由 + `agent_runs` | 能问"谁喜欢茶"，能问"她上次说的那事" |

### W16-W18 · 论文与答辩

| 周 | 任务 |
|---|---|
| W16 | 对比实验（纯 RAG vs 混合路由 / 带半衰期 vs 不带）+ 数据整理 |
| W17 | 论文撰写 |
| W18 | 演示准备（含离线回放模式）+ 答辩排练 |

## 3. 验收规则

双轨项目的验收必须分四层。**任何一层不通过，项目都不算成。**

### A. 功能验收（做得出来吗）

| 模块 | 通过标准 |
|---|---|
| 投喂 | 手机相册多选 10 张 → 上传成功 → 5 分钟内出确认卡片 |
| 抽取 | 一张清晰聊天截图，能抽出 ≥ 1 条有效信息，且带出处 |
| 归属 | 20 人候选池下，归属准确率 ≥ 90% |
| 确认 | 一条卡片可完成 ✓/✗/改归属/改内容 四种操作 |
| 画像 | 打开档案，综述 + 标签 + 时间线 + 往来四块齐全 |
| 日历 | 农历生日能正确换算为当年公历，事件能重复 |
| 提醒 | 生日 T-3 当天 08:00 收到企业微信消息，含建议 + 依据 + 话术 |
| 通道 | 主通道失败时自动降级到备用，且通知到用户 |
| 数据 | 单个人可一键导出（含原图）和一键删除 |
| **多用户隔离** | 两个账号交叉访问，互相查不到任何数据；直接改 URL 里的 id 返回 404/403，**且不报数据库错误**（RLS 生效的表现） |

### B. 质量验收（好不好用）

| 指标 | 目标 | 说明 |
|---|---|---|
| **事实抽取准确率** | ≥ 85% | 抽 50 条人工核对；这是生死线 |
| **金额/日期抽取准确率** | ≥ 95% | 错一次就送错礼，阈值必须更高 |
| **确认通过率**（✓ 占比） | ≥ 80% | 低于 70% 说明抽得太滥，用户会烦 |
| **投喂到出卡片延迟** | ≤ 60 秒 | 超过就会觉得"卡"，用不下去 |
| **提醒送达率** | ≥ 99% | 漏一条生日就是产品失败 |
| **提醒误报率** | ≤ 10% | 说"他冷了"结果人家好好的，两次就不信了 |
| **建议采纳率** | ≥ 50% | 用户看了建议后按建议执行的比例 |

### C. 产品验收（有没有价值）

**这是最重要也最容易被跳过的一层。** 用四周时间，问自己五个问题：

| # | 问题 | 通过标准 |
|---|---|---|
| 1 | 我连续用了多少天？ | **≥ 30 天不断** |
| 2 | 有没有漏过生日？ | **0 次** |
| 3 | 见人前会不会先打开档案？ | 一个月 ≥ 20 次 |
| 4 | 送礼物时还会想"去年送的啥"吗？ | 不会，直接查 |
| 5 | 如果明天关掉它，我会不会不舒服？ | **会** |

> 第 5 条是终极标准。如果答案是"不会"，说明它只是个有趣的玩具。

### D. 论文验收（能不能过）

| 项 | 标准 |
|---|---|
| 三个技术支点 | 多模态抽取 / 混合路由 / 主动提醒，**每个都有代码 + 可展示的中间产物** |
| 对比实验 | 至少两组量化对比（纯 RAG vs 混合路由、带半衰期 vs 不带） |
| 可解释性 | 现场能调出任意一条抽取记录、任意一次路由决策，逐字段讲 |
| 创新点 | 需求感知 2×2、记忆半衰期、HITL 确认机制，选两个讲透 |
| 演示稳定性 | 离线回放模式跑通，断网也能演示完整流程 |

## 4. 风险与降级

按"发生概率 × 破坏力"排序。

| # | 风险 | 概率 | 破坏力 | 降级方案 |
|---|---|---|---|---|
| 1 | **自己不用**（做完就搁置） | 中 | **致命** | W2 就上线；每周固定"下播后归档"仪式；把"今日页"设为手机主屏 |
| 2 | **VLM 抽取不准**，档案被污染 | 高 | 高 | 阈值下调、更多进确认队列；卡片必须显示原文出处；宁可少抽不可错抽 |
| 3 | **投喂太麻烦**，两周后放弃 | 中 | 高 | 手机相册直选；微信分享直达；上传后不等结果（后台处理） |
| 4 | 抽取太慢（>60s） | 中 | 中 | 异步 + 通知；大图先压缩；批量排队 |
| 5 | 模型 API 挂了 / 答辩断网 | 中 | 中 | **离线回放模式**（fixture 预录），成本低，强烈建议 |
| 6 | 归属猜错，记到别人头上 | 高 | 中 | 一键改归属；改完记录，用于优化；高价值信息强制确认 |
| 7 | 农历库跨年失效 | 中 | 中 | 封装 `FestivalService`，库失效时手动补数据 |
| 8 | 提醒误报（说人凉了其实没凉） | 中 | 中 | 多因子同降才报警；措辞留余地；只提示不自动行动 |
| 9 | 工期不够 | 中 | 中 | 见下方砍功能顺序 |
| 10 | 服务器成本/运维负担 | 低 | 低 | 1 核 2G 够用；Docker 一键部署；每月自动备份 |

### 4.1 工期不够时的砍功能顺序

**从后往前砍，绝不砍前面三条**：

```
① 前端换皮只做核心四屏（登录/今日/人/档案），其余保留丑版
② 砍 .ics 导出（可选功能）
③ 砍知识层 RAG（记忆层保留，建议仍可用档案生成）
④ 砍 AI 动态待办（保留固定模板）
⑤ 砍对话式问答（保留结构化筛选）
⑥ 砍需求感知（保留温度，作为纯展示）
⑦ 砍关系温度（V2 整体推迟）
———————————————————————————
✂ 以下永不砍：
   · 投喂链路（唯一入口）
   · 确认队列（质量闸门）
   · 日期提醒 + AI 建议（核心价值）
   · 档案 + 综述（核心体验）
```

### 4.2 什么情况下该停

诚实地说，这个项目有失败的可能。三个止损信号：

1. **W6 结束时，抽取准确率仍低于 60%**，且调整 prompt 无改善 → 说明当前 VLM 能力不够支撑这个场景，应改为"纯手动 + AI 辅助建议"
2. **W12 结束时，自己一周用不到 3 次** → 说明需求不真，应把项目降级为"论文交付"，不再投入产品化
3. **W15 结束时，温度被自己判定为"没用"** → 说明 20 人规模下不需要状态判断，应把 V2 的篇幅全部让给抽取和画像

> 止损不是失败，是及时把资源挪到还能赢的地方。**提前想好什么时候停，比坚持到底更专业。**

## 5. 后期规划（毕设之后）

### 5.1 V3 · 泛化（3-6 个月）

| 步骤 | 做什么 |
|---|---|
| 1 | 把"主播版"的字段、话术、提醒规则抽成一个**行业包**（JSON 配置） |
| 2 | 做第二个行业包（销售版：公司、职位、采购周期、回款账期） |
| 3 | 找 3-5 个真实用户试用，观察哪些字段是通用的、哪些必须可配 |
| 4 | 开放注册（V1 已有邀请制 + RLS 隔离，这一步只是打开入口） |

**判据**：如果第二个行业包只需要改配置、不改代码，说明"机制通用、字段可配"成立。

### 5.2 商业化路径（可选，不承诺）

| 模式 | 定价 | 风险 |
|---|---|---|
| 个人订阅 | 99-199 元/年 | 用户会不会为"记人"付钱？需要验证 |
| 买断 + 自部署 | 399-599 元 | 部署门槛高，客服成本大 |
| 行业包订阅 | 基础版免费 + 行业包付费 | 最合理，但需要先有多个行业包 |

**竞品参照**：传统 CRM（太重太贵）、备忘录（免费但笨）、微信备注（太浅）。中间地带确实空着，但**"空着"也可能意味着"没人愿意付钱"** —— 这一点必须靠真实用户验证，不能靠推理。

### 5.3 不做的长期方向

- 不做团队协作（会变成另一个 CRM）
- 不做自动抓取（合规红线）
- 不做 AI 代聊（伦理红线）
- 不做平台/社区（分散精力）

## 6. 关键决策记录

记录这轮讨论中被定死的事，以及为什么。以后想改，先看这里。

| # | 决策 | 理由 | 日期 |
|---|---|---|---|
| 1 | 双轨：毕设即 MVP 首发，同一套代码 | 避免做两个东西；论文讲机制，产品讲价值 | 10-27 |
| 2 | 用 **Person × Relationship** 替代 `Person.type` 枚举 | 哥姐就是客户，一个人可持多角色 | 10-27 |
| 3 | 需求感知优先级：温度 > 生活切口 > 消费意图 | 温度不依赖 AI 判断，最可靠；消费意图误报代价最高 | 10-27 |
| 4 | 需求感知 = 温度 × 场景 的 2×2 | 单看温度会误判，单看场景无优先级 | 10-27 |
| 5 | 主数据链路 = 聊天截图 | 80% 有用信息在一对一私聊里 | 10-27 |
| 6 | 画像 = 综述 + 标签分层 | 综述负责"读一个人"，标签负责"筛一批人" | 10-27 |
| 7 | 推送只管最近 20 人（活跃窗口） | 社交带宽上限；砍掉复杂排序算法 | 10-27 |
| 8 | V1 只做记忆系统，温度放 V2 | 温度需 3-4 周数据才能算准，冷启动期必然是噪声 | 10-27 |
| 9 | V1 提醒可以日期驱动，但 **AI 建议不能砍** | 原则二：建议必须带依据 | 10-27 |
| 10 | 部署在自己的服务器 | 数据主权是卖点；代价是运维债 | 10-27 |
| 11 | 泛化路径 = 机制通用、字段可配 | 字段跨行业不可复用，硬做"万能字段"必死 | 10-27 |
| 12 | 记忆半衰期：事实会过期 | 静态标签会越用越脏，动态画像必须能衰减 | 10-27 |

## 7. 一页纸总结

如果只能记住五句话：

1. **它不是记录系统，是判断系统**——回答"我现在该做什么"，不是"他是什么人"
2. **人只做两件事：投喂和查看**——任何要求先整理的设计都是失败的
3. **知道什么时候不打扰，比知道什么时候打扰更难，也更值钱**
4. **第一版做记忆，第二版做判断**——需要数据积累的算法不能放在产品最前面
5. **先让自己天天用，再想给别人用**——自己不用，一切归零
