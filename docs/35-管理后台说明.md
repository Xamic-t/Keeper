# 35 · 管理后台说明（2026-11-03 重做）

> 用户原话：**「账号管理不该和设置混在一起，应该是一个管理员后台」**
> 「管理员登录进去就账号管理，包括整个的后台，可以看到用户有哪些行为。」
>
> 这份说明回答三件事：**在哪进、谁能进、里面有什么**。

---

## 一、形态：独立界面，不混在业务菜单里

| | 改之前 | 现在 |
|---|---|---|
| 入口 | 业务侧栏里一个「账号」齿轮，和今日/投喂并列 | 业务菜单里**没有了**；入口在左下角账号区、分隔线下面单独一行「⚙ 管理后台」 |
| 页面外壳 | 套业务侧栏（左侧还是今日/投喂/助理…） | **独立外壳**：自己的侧栏（概览 / 账号 / 行为 / 系统）+ 底部「← 返回应用」 |
| 内容 | 只有账号列表 | 概览、账号管理、**每个账号的行为量**、系统信息 |
| 登录 | — | **同一个登录页**。是 owner 才看得到入口；member 直接敲 `/admin` 会被送回业务首页 |

地址：`/admin`。账号：任何 `role=owner` 的账号（本地是 `Admin`）。

---

## 二、四个页签里有什么

### 概览
- 四张卡：账号数（含管理员/停用）、联系人总数、已确认事实（含待确认）、未完成待办（含投喂数）
- **谁在用**：按最近活跃排序的前 5 个账号
- **空账号提醒**：建了但一条数据都没有的账号会被点名列出来
  （「看起来 8 个账号，其实 7 个是空的」是后台最该先发现的事）

### 账号
- 列表：账号 / 角色 / 状态 / 最后登录 / 创建时间
- 新建账号（邀请制；初始密码必须由你指定，**系统没有默认口令**）
- 停用 / 启用、重置密码
- 服务端规则照旧：不能停用自己、不能停用或降级最后一个 owner

### 行为（这次新增的重点）
每个账号一行，九列数量 + 最近活跃：

| 列 | 含义 |
|---|---|
| 联系人 / 事实 / 待确认 | 记了多少人、确认了多少事实、还有多少堵在确认页 |
| 待办 / 往来 / 提醒已发 | 干了多少活 |
| 投喂 / 对话 | 用了多少次投喂、跟助理聊了多少句 |
| 最近活跃 | 登录、投喂、对话三者取最近 |

**只有数量，没有内容。** 想看某人记了什么，用他的账号登录——后台的边界到此为止。

### 系统
- 环境（dev/prod）、版本、业务日期、数据库健康
- **当前迁移版本**：部署或升级后先看这里，和代码不一致说明升级没跑完

## 三、为什么"行为"是逐个数出来的（实现说明）

RLS 是按 `app.user_id` 隔离的：一次查询只能看到一个人的数据。
后台要看"所有人的量"，但**没有**给 RLS 开后门（不加 `is_owner` 之类的旁路参数）——
那种做法一旦被记住，隔离就变成了一个能随手关掉的开关。

这里的做法是：**逐个账号开 session，以他的身份数他自己的数**，把数量汇总起来。
20 人规模、每人一次往返（子查询合在一条 SQL 里），几十毫秒。接口：
`GET /api/admin/overview`（仅 owner，见 `docs/07`）。

返回结构：

```json
{
  "accounts": {"total": 7, "owners": 1, "active": 7, "disabled": 0},
  "totals":   {"persons": 9, "facts": 7, "pending_confirmations": 0, "todos_open": 10,
               "ledger": 0, "reminders_sent": 0, "raw_inputs": 3, "chat_messages": 28},
  "users":    [{"username": "Admin", "role": "owner", "last_active_at": "...", "persons": 4, "...": 0}],
  "system":   {"app_env": "dev", "app_version": "0.1.0", "migration": "0007", "today": "2026-11-03"}
}
```

## 四、怎么验

```bash
# 1. 权限：member 拿不到后台数据
curl -s -b <member cookie> http://127.0.0.1:8000/api/admin/overview   # → 403 FORBIDDEN

# 2. 界面：Admin 登录 → 左下角「管理后台」→ 四个页签
open http://127.0.0.1:5173/admin

# 3. 自动回归
cd backend && uv run pytest tests/api/test_admin_overview.py -q   # 5 条
cd e2e && node run.mjs --only admin                              # member 进不去
```

自动化覆盖：`tests/api/test_admin_overview.py`（跨账号聚合、只出数量、停用标记、401/403）
+ `e2e/cases/admin.mjs`（member 看不到入口、直连 `/admin` 被送回首页）
+ `src/lib/adminFormat.test.ts`（数字/相对时间/空账号判定的 10 条）。

## 五、没做的（明确说清楚，别以为是漏了）

| 不做 | 为什么 |
|---|---|
| 管理员查看/编辑别人的具体内容 | 后台只做"有没有在用"。看内容要登录那个账号——这条边界比功能重要 |
| 操作审计日志（谁在什么时候改了哪个账号） | 现在只有账号级的 `last_login_at`。要做需要新表，属于 V2（见 `docs/29` D-8） |
| 删除账号 | 刻意不做：删了数据归属就断了。停用即可 |
| 图表/趋势 | 单人项目 20 人的量，表格比图表信息量高 |
