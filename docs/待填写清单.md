### 1. 数据库密码（2 个）

| 变量 | 填哪 | 怎么填 |
|---|---|---|
| `DB_PASSWORD` | 项目根 `.env` | 库 owner（`keeper`）的密码，自己生成：`python3 -c "import secrets;print(secrets.token_urlsafe(24))"` |
| `APP_DB_PASSWORD` | 项目根 `.env` | 应用连接角色（`keeper_app`）的密码，**必须和上面不一样** |

> 为什么两个：应用连库必须用**非 owner** 角色，否则 PostgreSQL 行级安全（RLS）会被静默绕过，
> 多用户隔离形同虚设，而且不报任何错。见 `docs/13-验收汇总.md` 的 P1。

**填完会怎样**：`docker compose up -d db` 时初始化脚本会自动建出 `keeper_app` 角色。

### 2. 会话签名密钥

| 变量 | 填哪 | 怎么填 |
|---|---|---|
| `SECRET_KEY` | 项目根 `.env` | 同上命令生成一串随机值 |

> 这个值泄露 = 任何人都能伪造登录 cookie。别用 `change-me`。

### 3. 模型 API Key（决定"投喂能不能识别"）

| 变量 | 填哪 | 说明 |
|---|---|---|
| `DEEPSEEK_API_KEY` | 项目根 `.env` | **主通道**，DeepSeek 开放平台申请 |
| `DASHSCOPE_API_KEY` | 项目根 `.env` | **备通道**，阿里云百炼申请。主通道挂了会自动切它 |

配套（一般不用改，除非你换服务商）：

```
VISION_PROVIDER=deepseek
VISION_MODEL=deepseek-flash
VISION_BASE_URL=https://api.deepseek.com/v1
FALLBACK_PROVIDER=qwen
FALLBACK_MODEL=qwen-vl-max
FALLBACK_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1
```

**没填会怎样**：系统照常能登录、建人、记往来，但**投喂的截图不会被识别**——
材料状态会变成 `failed`，错误码 `AI_UPSTREAM_ERROR`。
界面不会崩，只是识别不出内容。（这是刻意的：宁可不识别，也不编内容。）

> ⚠️ 如果你打算用别家 VLM，只要它是 OpenAI 兼容协议，改 `VISION_BASE_URL` + `VISION_MODEL` + Key 即可，代码不用动。

### 5. 第一个 owner 账号

系统是邀请制，没有注册接口。需要有一个 owner 账号来建其他号。

最省事的方式（本地执行一次）：

```bash
cd /Users/xamic/Customers_System/backend
uv run python - <<'PY'
from sqlalchemy import create_engine, text
from app.config import settings
from app.core.security import hash_password

engine = create_engine(settings.database_url)
with engine.begin() as conn:
    conn.execute(text("""
        INSERT INTO users (username, password_hash, display_name, role, is_active,
                           failed_attempts, keep_original_images)
        VALUES (:u, :h, :d, 'owner', true, 0, true)
        ON CONFLICT (username) DO UPDATE SET role = 'owner'
    """), {"u": "你的登录名", "h": hash_password("你设的初始密码"), "d": "你的名字"})
print("owner 账号就绪")
PY
```

之后用这个账号登录，在「设置」里可以再改密码；建别人的号用 `POST /api/admin/users`。

### 6. 推送通道（不做也能用）

两种方式，**二选一**：

| 方式 | 填哪 | 说明 |
|---|---|---|
| 界面里加（推荐） | 登录后「设置 → 推送通道」 | 填企微机器人 webhook，存进数据库，改完立刻生效 |
| 环境变量 | `.env` 的 `WECOM_WEBHOOK` | 全局兜底，库表里没有通道时用它 |

PushPlus 同理（`PUSHPLUS_TOKEN`）。两个都配就自动降级：企微失败 → PushPlus。

**通道拿不到怎么办**：提醒照样生成（`reminders` 表里有完整内容），只是推不出去，
可以在 `GET /api/reminders` 里看历史。

### 7. 每日任务的启动方式

提醒是定时任务生成的，两个选择：

| 方式 | 做法 |
|---|---|
| 服务器常驻 | `docker compose exec app uv run python -m app.jobs.daily --serve`（每天 08:00 跑） |
| 手动跑 | `docker compose exec app uv run python -m app.jobs.daily`（跑一次就退出） |

> 建议加进 `docker-compose.yml` 的 `app` 服务（同进程起一个 scheduler 更省事）——
> 这一步我**没有替你做**，因为它会让容器多一个常驻进程，
> 你确认要常驻我再改。

### 8. 生产环境的安全项

| 项 | 现在 | 生产要改成 |

## 三、需要你提供的素材（1 项）

### 9. 真实聊天截图（抽取准确率验收用）

W5 的验收标准是：**抽 30 张真实截图，事实准确率 ≥75%**；金额/日期准确率 ≥95%。
这个只能拿真实素材验，我这边没有你的聊天记录。

**怎么做**：

1. 找 30 张有代表性的截图（有对话、有金额、有生日最好）
2. 用「投喂」页传上去
3. 到「确认」页逐条核对，错的点驳回
4. 统计：对的条数 / 总条数 ≥ 75% 算过

**如果准确率不达标**：把 `VISION_MODEL` 换成 `qwen-vl-max` 再跑一遍（文档里写明：
低于 75% 立刻切通义做主力，不要恋战）。
